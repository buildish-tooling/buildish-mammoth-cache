This release reduces restore indexing and adds an opt-in Gradle read-only dependency
layer for qualified distributed workers. It also enforces a fresh managed cache area
at prepare and improves capture and finalization diagnostics. Expect cold caches and
upgrade cooperating jobs together: the generation format and Gradle partition layout
are incompatible with 0.3.x. The Actions continue to run on Node.js 24.

## Highlights

- Restore eligible aggregate Gradle subtrees with guarded intact-directory moves,
  retaining installation records at move and split boundaries instead of indexing
  every descendant. Read-only jobs and distributed workers can skip descendant
  collection beneath eligible intact roots. Writable standalone jobs and aggregators
  still collect the pre-build metadata summary needed for exact object reuse.
- Trust exact Mammoth-published native objects and successful SDK extraction for
  intact subtree interiors. Preserve object/envelope matching, owned staging,
  boundary checks and guarded moves. Strict incoming worker validation remains.
  Maven, independent snapshots, worker overlays and authoritative pruning retain
  detailed handling. SDK downloads and archive extraction are unchanged.
- Require initially empty managed contents before restore. Existing directories,
  excluded contents and unmanaged settings can remain. Reject selected files with
  their partition and path before wrapper provisioning or backend access. Gradle
  prepare rejects detected daemons and uncertain process inspection without stopping
  daemons. Read-only restores, cache misses and unavailable backends use the same
  admission contract.
- Split Gradle's `modules` preset into `dependency-artifacts` for
  `caches/modules-2/files-2.1/**` and `module-support` for `caches/jars-*/**` and
  `caches/resources-*/**`. Keep `caches/modules-2/metadata-*/**` under the existing
  single-writer `dependency-metadata` partition.
- Add `dependency-cache-layer`, disabled by default. Eligible warm writable distributed
  workers resolve inherited dependencies from an invocation-owned read-only seed
  outside writable capture. Misses use the writable home and contribute normally.
  Initial activation requires a positively resolved Gradle **9.6.1** wrapper, a
  compatible artifact/metadata cohort, no selected single-writer ownership and
  `restore-cleanup-mode: none`.
- Emit `gradle-ro-dep-cache` and normally export `GRADLE_RO_DEP_CACHE` on activation.
  Set `export-layer-environment: false` to configure consumers from the output
  yourself. Keep consumers within prepare/post; post settles registered consumers
  before retiring the seed. Uncertain ownership or quiescence preserves diagnostic
  state rather than deleting a potentially live path.
- Add capture statistics and bounded actual skipped-file examples, plus timings for
  worker acceptance, staging, native validation/indexing, snapshot copying, activity
  preparation and retirement. Remove the overbroad configuration-cache directory
  exclusion that also matched Gradle distribution documentation and sources;
  the separate encryption key remains excluded.
- Update tar-stream to 3.3.0 with the reviewed strict-profile patch, and use the
  TypeScript 7 compiler alongside the TypeScript 6 API required by lint tooling.

## Upgrading from 0.3.0

- Upgrade all cooperating workers, snapshot writers, aggregators and readers
  together. Both tools use generation v3; older families start cold. Partition
  objects remain v2 and worker TAR remains v2. Local handoffs change for restore
  and layer handling. Do not mix main/post bundles from different revisions.
- Migrate explicit `modules` overrides: the retired preset is rejected. Use
  `dependency-artifacts` and/or `module-support` as appropriate; disable both to
  disable its former artifact/support coverage. Built-in dependency paths now
  target `modules-2/files-2.1` and `modules-2/metadata-*`. Other layouts require
  explicit custom includes.
- Run Mammoth before Gradle, Maven or another cache restorer. Use a fresh dedicated
  home on persistent runners and explicitly provision required unmanaged settings.
  Existing managed files are not imported or automatically deleted. Keep roots
  exclusive throughout prepare, build and post. Gradle inspection is point-in-time
  and can reject daemons belonging to another home; Maven relies on caller exclusivity.
- Use the same `dependency-cache-layer` value across cooperating Gradle jobs. It
  selects a distinct family whose publishers retain eligible aggregate dependency
  partitions, even when no worker seed activates. Retention can grow storage;
  periodic seed sweeps and capacity eviction are deferred. Metadata keeps its
  complete-snapshot writer policy.
- Other Gradle versions, incomplete cohorts, custom dependency layouts, read-only
  jobs and other roles use ordinary installation. An existing nonempty
  `GRADLE_RO_DEP_CACHE` conflicts with eligible layered prepare and fails before
  provisioning/backend access. Maven layering is not included.
- Directory-entry limits apply to directories actually enumerated. An intact
  aggregate Gradle restore can accept a subtree that a publishing job later opens
  for its summary and rejects at a deeper directory limit. Working-memory limits
  remain independent.

Layering leaves wrappers, transforms, DSL and task-output caches on their ordinary
paths and still downloads/extracts the seed. No universal elapsed-time, repository-size
or memory improvement is promised. Base change detection remains metadata-based and
can miss byte rewrites that preserve the observed metadata.

Review the exact `v0.4.0-rc1` candidate tag and use `v0.4.0` after final promotion,
at `actions/github/gradle` or `actions/github/maven`. Ordinary source branches omit
the generated executable bundles; use a materialized release or candidate ref.
