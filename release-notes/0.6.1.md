This patch makes producer-name collisions between distributed matrix cells
visible and adds documentation for matrix jobs and restricted action allow-lists.

## Highlights

- Explain producer-name collisions between matrix cells. All cells of a matrix
  job share one job ID, which is also Mammoth's default producer name. When two
  cells uploaded the same worker artifact name, the second upload was rejected
  and that cell's contribution was lost with only a generic
  `Raw worker upload unconfirmed` warning. When the names differed, the
  aggregator failed with a bare `Ambiguous raw worker artifacts` error. Both
  messages now say to give each cell its own `github-job-name`, list those names
  in `dependent-jobs`, and link to the matrix-jobs section of the 0.6.1 docs.
- Document distributed matrix jobs, including a complete workflow that is also
  available as `examples/gradle-distributed-matrix.yml`.
- Document the allow-list entries needed in repositories and organizations that
  allow only specified actions, with a pointer for Apache Software Foundation
  projects, and the resulting setup failure in the troubleshooting guide.
- Drop `actions/setup-java` from aggregator jobs in the docs and examples.
  Mammoth does not run Java, and an aggregator runs no build.

## Upgrade notes

- No action-input or workflow changes are required. Cache formats are unchanged,
  and existing 0.6.0 cache generations can be reused.
- Distributed matrix workflows that do not set a distinct `github-job-name` per
  cell were already affected by the collision. After upgrading, they report it
  through the new messages; follow the linked guidance to fix the workflow.
- Aggregator jobs can drop `actions/setup-java` unless they also run Gradle or
  Maven.

Review `v0.6.1-rc1` as the first release candidate and use `v0.6.1` after final
promotion.
