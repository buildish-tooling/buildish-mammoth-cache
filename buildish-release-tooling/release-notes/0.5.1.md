This patch fixes two Gradle configuration-cache problems.

Since 0.5.0, the first build of a Gradle installation on a layered worker
(OverlayFS or the read-only dependency seed) stored a configuration-cache entry
that the next build could not reuse. Gradle reported that a file in Mammoth's
`registrations/` directory "has been created". Builds that run the same Gradle
build twice and expect reuse, such as TestKit compatibility tests, failed.
Registration now writes its record without checking for it first, so Gradle no
longer records the file as a build input.

The Gradle build summary now also lists builds that reuse a configuration-cache
entry. Previously, such builds were missing from the summary, and a reused entry
was never reported as a configuration-cache hit.

No action-input or workflow changes are required. Cache formats are unchanged,
and existing 0.5.0 cache generations can be reused. Review `v0.5.1-rc1` as the
first release candidate and use `v0.5.1` after final promotion.
