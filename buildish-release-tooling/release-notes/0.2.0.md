# Mammoth Cache 0.2.0

This minor release improves Gradle and Maven cache coverage, distributed recovery,
and publication efficiency. It changes cache identities and worker transport;
upgrading starts a cold cache family.

## Highlights

- Save changed partitions independently and reuse unchanged partition objects.
  Publish the generation record only after required objects are available. Missing
  objects recover as cold partitions while unrelated valid partitions remain usable;
  connected Maven directory owners recover together. Changed partitions still
  upload in full. Native archives and move-based restores avoid additional base
  payload copies on the normal path.
- Replace before/after full-content inventories with post-prepare timestamp
  cutoffs. Freeze writable activity decisions before Mammoth reads payloads.
  Read-only finalize skips publication-oriented scans, snapshot capture, GC and
  saves; restore integrity checks still apply.
- Cache Gradle dependency metadata through a default `dependency-metadata`
  single-writer partition. Standalone jobs own their snapshots automatically;
  distributed jobs can designate an existing worker or the aggregator as writer.
  Complete snapshots propagate removals without merging Gradle's binary indexes.
- Add a default `groovy-dsl` partition that preserves complete compiled-script
  workspaces, both metadata files and empty output directories. Conflicting views
  select one producer's complete workspace. Existing Kotlin DSL coverage remains.
- Share cache families across Java versions, operating systems and architectures
  by default. Build tools and project inputs determine output reuse. Cross-OS
  archives preserve portable paths and repair known distribution launchers on POSIX.
- Preserve Maven `_remote.repositories` origin markers and complete managed
  directory views. Strict conflicts remain the default. The optional partition
  policy `conflict-handling: choose-worker-directory` selects a complete worker
  directory when independent contributions conflict.
- Retain worker envelopes after successful and failed aggregation, allowing
  selective and aggregator-only retries within artifact availability. New input
  `worker-artifact-retention-days` requests 7 days by default and accepts whole days
  from 1–400, subject to backend and organization limits. Shorter retention narrows
  the retry window; successful aggregation does not delete the envelopes.
- Write verified Gradle wrapper metadata beside the versioned JAR as
  `gradle-wrapper-<version>.jar.sha256` and `.jar.asc`, so compatible custom
  launchers can retain the provisioned JAR.
- Add an adoption and migration guide covering topology, ownership, write policy,
  remaining costs, Maven scope, and small pilots with rollback. Extend hosted CI
  with Linux, Windows and macOS ARM64 workers, Linux aggregation, fresh native
  readers, and Java 21/25 sharing checks for Gradle and Maven.

## Upgrading from 0.1.x

- Upgrade cooperating workers and aggregators together. Old cache families start
  cold, and older worker envelopes are not compatible with the new transport.
  Start a new workflow run when changing versions rather than combining retained
  envelopes from different implementations.
- Review namespaces and writer policy. Java, OS and architecture no longer create
  separate families automatically; use `cache-key-prefix` when isolation is needed.
  Independent standalone writers publish their own views, not a merged union.
- For distributed Gradle jobs, configure the same `dependency-metadata` writer and
  partition settings on all participants. Without a writer, the previous metadata
  snapshot is retained with a warning. A writer's snapshot covers its own
  resolution view, not every worker's metadata. Managed snapshot files are
  replaced during prepare, including clearing them on a miss, even when ordinary
  restore cleanup is disabled.
- Start with a fresh dedicated Maven user home when upgrading from the previous
  marker-excluding policy. Keep repository/mirror configuration compatible. Maven
  snapshots and local installs remain included by default; exclude complete
  coordinate/version directories when appropriate and retain separate delivery of
  required build artifacts. Directory-winner selection can discard losing
  classifiers, origin entries or local installs; enable it deliberately.
- Update scripts that consume the old wrapper sidecar names
  `gradle-wrapper-<version>.sha256` or `.asc`. Provisioning writes the new
  `.jar.sha256` and `.jar.asc` names; existing old sidecars are left untouched.
- Timestamp GC now uses file age plus current-build activity protection, not a
  historical last-use manifest. Hidden filesystem accesses or clock behavior can
  cause useful files to be evicted and downloaded or recomputed later.
  `cache-gc-mode: off` disables deletion, not tracking or snapshot work.

The Gradle and Maven actions continue to use the Node.js 24 runtime. Review the
exact `v0.2.0-rc1` candidate tag and use `v0.2.0` after final promotion, at
`actions/github/gradle` or `actions/github/maven`. Ordinary source branches omit
the generated executable bundles; use a materialized release or candidate ref.
