This release adds OverlayFS-based capture on eligible Linux jobs and replaces
per-publication timestamp GC with periodic sweeps. Upgrade cooperating workers and
aggregators together: workers can emit worker-identity evidence that older
aggregators do not accept.

## Highlights

- Add `overlay-fs`, enabled by default. Eligible warm, writable Linux jobs mount the
  managed cache with OverlayFS and use the upper layer to find changes instead of
  walking inherited files. Gradle workers mount the Gradle user home; Maven workers
  mount only the local `repository/` directory. Warm standalone and aggregator
  publishers can prove an unchanged generation from bounded overlay evidence and
  reuse its archives. A recoverable mount failure falls back to the ordinary
  writable path. On GitHub-hosted Linux, mount operations use noninteractive `sudo`.
- Eligible Gradle workers prefer OverlayFS over the read-only dependency seed while
  GC is fresh. Set `overlay-fs: false` to skip mount probing and keep using the seed.
- Run timestamp GC as a periodic sweep of inherited files in aggregate partitions.
  Add `dependency-gc-interval-days` (default `3`) and
  `dependency-gc-force-grace-days` (default `1`, or `off`). A successful sweep
  records its completion in the published generation.
- Add the `dependency-gc-due` output (`true`, `false` or `unknown`) and a
  `prepare-only` job mode. A planning job can emit the due hint without installing
  the cache or provisioning the build tool, so workflows with conditional workers
  can run the full worker set when a sweep is due.
- Due workers use ordinary writable capture and report qualified usage. A full sweep
  requires evidence from every effective `dependent-jobs` name in the current run and
  attempt for the exact generation the aggregator restored. An aggregator can force a
  sweep with incomplete coverage after the grace period.
- Keep Mammoth control records and staging in a sibling `.mammoth.<id>` directory
  next to the dedicated Gradle or Maven home, on the same filesystem.

## Upgrade notes

- With OverlayFS active, post unmounts the cache and discards the job's local writes
  within the mount after capture or publication. Set `overlay-fs: false` if later
  steps or persistent runners need those changes on disk after post.
- The parent of a dedicated home must be writable by the runner, and the sibling
  `.mammoth.<id>` directory must remain until post. On persistent runners, use a
  fresh dedicated home per invocation.
- Generations published before 0.5.0 have no recorded sweep. They are due
  immediately, and forcing is immediately eligible unless
  `dependency-gc-force-grace-days` is `off`.
- To count conditional or matrix workers towards full sweep coverage, list their
  Mammoth job names in `dependent-jobs`.

Review `v0.5.0-rc1` as the first release candidate and use `v0.5.0` after final
promotion.
