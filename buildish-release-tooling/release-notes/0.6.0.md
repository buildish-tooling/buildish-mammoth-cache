This release fixes config-file values that action defaults silently overrode,
makes periodic GC more conservative after failed Gradle builds, and lets a
distributed aggregator proceed when a dependent job uploaded no artifact.

## Highlights

- Config-file values now apply to every input. Previously, an input with a default
  in `action.yml` ignored its config-file value, because GitHub passes metadata
  defaults to the action as if the workflow had set them. This affected, for
  example, `job-mode`, `cache-key-prefix`, `cleanup-enabled`, `cache-gc-mode` and
  `cache-gc-older-than-days`. Defaults now apply after config-file resolution:
  direct inputs win, then config-file values, then defaults. The input
  descriptions state each default.
- A Gradle worker whose build failed, or started but recorded no result, no longer
  counts towards full sweep coverage. Such a build may have used only part of its
  dependencies, for example after failing to resolve settings plugins, and a sweep
  could evict entries that later builds download again. The worker still publishes
  its changes. The sweep waits for a run in which every listed worker succeeds, or
  for the forced sweep after `dependency-gc-force-grace-days`.
- The Gradle build summary lists builds that started but recorded no result. Such
  builds failed before settings evaluation or were interrupted, and previously did
  not appear in the summary at all.
- Add `allow-missing-dependent-jobs`, enabled by default. When a job in
  `dependent-jobs` uploaded no artifact, for example because it was skipped, failed
  before the Mammoth step, or was cancelled before its post step, the aggregator
  warns and merges the available workers. Previously the whole aggregation failed,
  discarding every other worker's changes. A missing job still prevents full sweep
  coverage, and snapshot partitions of a missing writer keep the previous snapshot.

## Upgrade notes

- Cache formats are unchanged, and existing 0.5.x generations can be reused.
  Workers and aggregators of 0.5.x and 0.6.0 can be mixed: a worker that withholds
  sweep evidence writes the ordinary worker identity that 0.5.x aggregators accept.
- Review your config files. Values that were previously overridden by action
  defaults now take effect. Workflows that repeated such values as direct inputs
  to work around the problem can drop them.
- Aggregators no longer fail when a listed job uploaded no artifact. Set
  `allow-missing-dependent-jobs: false` to keep the previous failure, for example
  to detect a misspelled job name or a missing `needs` entry early.
- List every worker in `dependent-jobs`, including conditional ones. A list
  shortened to the workers that ran also shortens the coverage requirement and lets
  a sweep evict entries that only the omitted workers use.
- A Gradle build that is expected to fail, for example one launched by an `Exec`
  task, now defers sweeps for its worker. Set
  `BUILDISH_MAMMOTH_CACHE_GRADLE_SKIP_BUILD_RESULT_CAPTURE=true` in that build's
  environment to exclude it. Builds launched by `Test` tasks are already excluded.
  With `dependency-gc-force-grace-days: off`, a worker that fails in every run
  prevents sweeps.
- Standalone jobs and Maven workers are unchanged: their sweep decisions do not
  depend on build outcomes.

Review `v0.6.0-rc1` as the first release candidate and use `v0.6.0` after final
promotion.
